## 1.0.0-beta.2

`ReleaseDataSnapshot` and its JSON coders moved down to SwoopKit 1.0.0-beta.2, so SwoopMistKit can write the same snapshot JSON that SwoopCloudKit reads. SwoopCloudKit now re-exports SwoopKit, so code that only does `import SwoopCloudKit` keeps compiling unchanged.

* `ReleaseDataSnapshot`, `JSONEncoder.iso8601PrettySorted`, `JSONDecoder.iso8601` and `JSONDecoder.decodeValue(_:from:)` now come from SwoopKit, unchanged and with the same JSON; SwoopCloudKit's copies are removed so a module importing both packages has no ambiguous members. SwoopCloudKit re-exports SwoopKit (`@_exported public import SwoopKit`), so `import SwoopCloudKit` code, including `SwoopCloudKit.ReleaseDataSnapshot`, still compiles. `ReleaseDataCacheFile` and `JSONEncoder.encodeAsserting(_:)` stay here (brightdigit/Stewed#194) by @leogdion in https://github.com/brightdigit/SwoopCloudKit/pull/2
* Depend on SwoopKit `from: "1.0.0-beta.2"` (brightdigit/Stewed#194) by @leogdion in https://github.com/brightdigit/SwoopCloudKit/pull/2

**Full Changelog**: https://github.com/brightdigit/SwoopCloudKit/compare/1.0.0-beta.1...1.0.0-beta.2

## 1.0.0-alpha.1

The first release of SwoopCloudKit (formerly BushelCatalog): a read-only reader for the public CloudKit database of `iCloud.com.brightdigit.Swoop`, using native `CloudKit.framework`, that maps each `CKRecord` onto the SwoopKit records SwoopMistKit writes. It needs no API token or server-to-server key; access comes from the app's iCloud entitlement. It depends on [SwoopKit](https://github.com/brightdigit/SwoopKit) `from: "1.0.0-beta.1"`, and this release adds iOS, watchOS, tvOS, visionOS and Mac Catalyst to macOS and Linux. It's an alpha: the API may still change before 1.0.0. Add it with `.package(url: "https://github.com/brightdigit/SwoopCloudKit.git", from: "1.0.0-alpha.1")` and the `SwoopCloudKit` product.

* Add `CloudKitReleaseCatalog`, which reads every page of `SDKVersion`, `XcodeVersion` and `SimulatorRuntime` and maps them to SwoopKit's `SDKVersionRecord`, `XcodeVersionRecord` and `SimulatorRuntimeRecord`. Records that don't map come back as `CloudKitRecordSkip`s instead of failing the fetch. `accountStatus()` returns a `CloudKitAccountStatus`, and failures throw a typed `CloudKitCatalogError` (brightdigit/Stewed#153) by @leogdion in https://github.com/brightdigit/SwoopCloudKit/pull/1
* Add `CloudKitRestoreImageService`, which lists `RestoreImage` records (one page) as `CloudKitRestoreImage`s for Bushel's catalog. It and the `CKRecord` value helpers are seeded from Bushel's `BushelCloudKitDebug` (v3.0.0-alpha.3, `46b6240`) by @leogdion in https://github.com/brightdigit/SwoopCloudKit/pull/1
* Add `ReleaseDataSnapshot`, `ReleaseDataCacheFile` (`formatVersion` 1; `decode(_:)` checks the version first and throws a typed `ReleaseDataCacheError`) and `CloudKitReleaseCatalog.fetchSnapshot(now:)`, which gives a snapshot with no runtime records when the environment has no `SimulatorRuntime` record type. Add the JSON coders they use: `JSONDecoder.iso8601`, `JSONDecoder.decodeValue(_:from:)`, `JSONEncoder.iso8601PrettySorted` and `JSONEncoder.encodeAsserting(_:)`. Moved from Stewed's StewedKit with the JSON unchanged; a cache file written before the move still decodes and re-encodes to the same bytes (brightdigit/Stewed#124) by @leogdion in https://github.com/brightdigit/SwoopCloudKit/pull/1
* The default container is `iCloud.com.brightdigit.Swoop` (was `iCloud.com.brightdigit.Bushel`) (brightdigit/Stewed#163, brightdigit/Stewed#175) by @leogdion in https://github.com/brightdigit/SwoopCloudKit/pull/1
* Support every Apple platform: the CloudKit readers build on macOS 14, iOS 18, watchOS 11, tvOS 18, visionOS 2 and Mac Catalyst 18, where earlier development builds were macOS-only. The snapshot, cache file and JSON helpers also build on Linux, where everything under `#if canImport(CloudKit)` is compiled out and the CloudKit test suites are disabled by @leogdion in https://github.com/brightdigit/SwoopCloudKit/pull/1
* Depend on SwoopKit `from: "1.0.0-beta.1"` instead of its `simulator` branch. Requires Swift 6.4 (swift-tools-version 6.4, Swift 6 language mode; Xcode 27.2 on Apple platforms) by @leogdion in https://github.com/brightdigit/SwoopCloudKit/pull/1
* Add a DocC catalog with articles on reading release data from CloudKit and on caching it, built by `Scripts/docc.sh` (`make docs`) with warnings as errors; there is deliberately no swift-docc-plugin dependency (brightdigit/Stewed#160) by @leogdion in https://github.com/brightdigit/SwoopCloudKit/pull/1
* CI (pull requests only): Linux on the `swift:6.4` noble and jammy images (non-CloudKit code), SPM builds on macOS and the iOS simulator on every PR, xcodebuild for macOS, watchOS, tvOS and visionOS on PRs into `main` or a semver branch, all on Xcode 27.2, plus the DocC build, swift-format and SwiftLint, and an `unsafeFlags` check. CodeQL is removed until it supports Swift 6.4 by @leogdion in https://github.com/brightdigit/SwoopCloudKit/pull/1
* Known limitation: the record types grant `READ` only to `_icloud`, so reading needs a signed-in iCloud account (`accountStatus()` must be `.available`), and the app needs the iCloud (CloudKit) capability with the `iCloud.com.brightdigit.Swoop` container. A development-signed build reads the Development environment; Developer ID and App Store builds read Production
* Known limitation: `CloudKitRestoreImageService.fetchRestoreImages(limit:)` returns one page (up to `limit`, default 100) and throws untyped errors
* Known limitation: the tests use hand-built `CKRecord`s and JSON fixtures and never open a `CKContainer`, so there is no live CloudKit coverage in CI. Mac Catalyst has no CI lane
